# 叙述深度与范例

科研范例的组织方式取自用户提供的项目叙述，已省略姓名、地点、具体型号与指标，并作教学改写。竞赛例为虚构。它们用于学习如何组织事实，不能作为其他人的项目材料。

## 从原项目学什么

原范例先说明低成本监测需求，再交代本人负责设备研发与数据处理；行动依次展开为设备设计、定标、田间数据获取、基础反演、模拟场景评估和动态监测验证。读者可以理解每一步为什么出现，以及前一步怎样支持后一步。

应迁移的是这种具体程度和推进逻辑。别人的项目可以只有调查、设计或复现，不必具备硬件、机理模型、机器学习或完整田间验证。

| STAR | 原范例对应的组织内容 |
| --- | --- |
| S | 连续农情监测的设备成本与部署需求，叶绿素动态估计问题 |
| T | 本人负责设备研制、数据处理及相关反演工作；不同阶段分别说明 |
| A | 设备设计与校准、采集数据、建立基础方法、构建模拟数据与模型、开展验证，并说明相关原因 |
| R | 各阶段实际完成的设备、数据和验证结果，区分模拟与田间条件 |

原项目有多个相连阶段，适合分段组织。简单项目只需一条清楚的 STAR，不为篇幅强加阶段。

## 科研叙述示例

下面的阶段结果来自范例中明确描述的工作，教学改写不保留精度结论。实际使用须换成当前用户的真实材料。

> 本科阶段，我围绕低成本作物光谱观测与叶绿素含量估计开展科研训练。项目希望通过可持续采集的观测数据支持作物状态监测，我主要负责观测设备研发、数据处理与相关反演流程的实现。
>
> 在设备研制方面，我完成传感器外围电路、外壳和采集程序的设计，并使用参考仪器开展定标与校准。随后，我依托田间试验获取不同生育期的冠层光谱数据，为后续反演研究提供观测基础。
>
> 在模型研究方面，我首先使用一维辐射传输模型和查找表方法建立基础反演流程。为考察复杂冠层结构对估计结果的影响，我进一步引入三维模拟场景生成光谱数据，并在此基础上开展模拟数据与机器学习结合的反演实验。随后，我面向连续观测数据中的光照与几何变化，构建多时相特征用于动态估计，并将模型输出与田间参考数据进行对照验证。
>
> 目前，我已完成设备研制和定标，积累了田间多时相观测数据，并对反演流程开展了模拟数据评估与田间初步验证。

这一写法用背景和任务解释行动，再按实际过程展开。若要补写“显著提升”“完成动态监测”等结果判断，应有对应验证材料；不能仅因行动丰富就补出性能结论。已知指标应附条件，未知指标不沿用原范例。

### 这一深度怎样通过对话得到

以下为整体项目链已经初步理清后，进一步补充专业细节的教学改写，不是开场流程或逐字聊天记录。已有材料能直接回答的内容应先提取，不再照着本例重复问。首次入口及粗略描述的处理以对话引导为准。

**用户：** 我用了一个一维模型和一个三维模拟工具做参数反演。

**助手：** 三维模拟工具在你的流程里具体承担哪一步？

**用户：** 我搭建场景、生成仿真光谱，用来评估基础反演方法。

**助手：** 可以写清“构建三维场景并生成光谱数据，用于评估反演表现”。你为什么需要这一步评估？

**用户：** 希望考察不同冠层结构条件下的表现。

**助手：** 这就把方法选择的原因补上了。之后有没有使用真实观测数据进行验证？

**用户：** 后续用田间观测数据作了初步验证，参考值来自仪器读数经经验关系换算。

**助手：** 结果段会把模拟评估与田间验证分开，也会保留参考值是间接换算的条件。具体指标只采用你能确认的数值。

这里的追问逐步明确方法作用、选择原因和验证口径，既保留研究深度，也不替用户补出“显著提升”或直接测量的结论。

## 竞赛叙述示例

假定已知事实：校园数据分析竞赛，以食堂排队为题；学生与队友共同设计问卷，本人统一时间选项、清理回收表格并制作分组图，模型由队友完成，团队完成方案与答辩，奖项名称尚未确认。

> 在校园数据分析竞赛中，我们围绕食堂不同时段的排队情况开展调查，希望为用餐安排提出分析建议。我主要负责问卷设计中的选项统一、回收数据整理和描述性分析，模型部分由队友承担。
>
> 为便于比较不同食堂和时段，我与队友共同设计调查问卷，并负责统一时间选项。回收数据后，我检查并删除空白及重复提交记录，按食堂和时段汇总数据、制作图表，再将整理后的数据与统计结果交给负责建模的队友，支持后续方案讨论。
>
> 最终，我完成了清理后的调查数据和分组图表，团队据此形成分析方案并完成竞赛答辩。

这个项目的行动深度来自具体工作与协作关系。不能将其扩写为独立建立预测模型、证明排队原因或已经优化真实食堂运行。奖项确认后可以说明团队获得的奖项，但奖项不代替项目产物和个人贡献。

## 相同事实可以写到什么程度

| 表达 | 判断 |
| --- | --- |
| “负责数据处理，提升了综合能力” | 过于笼统，应追问输入、操作和交付物 |
| “删除空白及重复提交记录，按食堂和时段汇总数据并制作图表” | 有具体行动，可以作为经历事实 |
| “独立设计智能模型，显著改善校园拥堵” | 上述材料不支持，应删去或澄清 |
| “项目仍在推进，目前已完成数据整理，尚未进行实地验证” | 结果边界清楚，可以用于未结束的项目 |

最后的认识应由用户真实表达。例如用户主动谈到分工接口的重要性，可以在结果后写相应认识；不能统一替每个人生成“深刻理解了完整科研链路”。
