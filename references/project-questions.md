# 科研与竞赛追问

材料入口和暂定项目链已经处理、整体过程初步清楚后，按需读取对应部分。这是后续可选问题，不是开场问卷；不能在用户第一次模糊描述后立即逐条追问技术原理。一次沿着当前回答选一个关键点，已有答案就跳过，不强制所有项目采用相同方法或指标。

## 科研项目

| 已知内容或缺口 | 可选的下一问 | 要得到的信息 |
| --- | --- | --- |
| 只知道课题名称 | “这个研究具体希望弄清或解决什么问题？” | S，具体问题；不预设必须提出新理论 |
| 目标笼统 | “做到什么程度，你们会认为这项任务已经完成？” | T，目标与完成标准 |
| 本人角色不清 | “其中哪一步由你负责，最后要交付什么？” | T，本人职责 |
| 只说采数据、做调查或做实验 | “你实际获取或整理了什么材料？这部分后来用在哪里？” | A，研究对象、输入与用途 |
| 只报一个模型或方法名 | “这个方法在整个流程里承担哪一步？” | A，方法作用 |
| 已知方法作用但缺少行动 | “这一部分你具体完成了哪些操作？” | A，执行、实现、调整或设计的边界 |
| 已知做法但缺少原因 | “当时为什么采用这个方法？如果不是你确定的，也可以说明是谁提出的。” | A，方案依据与决策归属 |
| 方法组合关系不清 | “前一个步骤产生了什么，后一个步骤怎样使用它？” | A，方法之间真实的衔接 |
| 说改进了原方案 | “原方案具体出现什么现象，你改动了哪一处？” | A，实际调整，不自动称为创新 |
| 说效果更好 | “你们根据什么实验、对照或分析作出这个判断？” | R，验证依据 |
| 给出一个指标 | “这个数值对应哪批数据、哪种评价条件？” | R，口径、单位与范围 |
| 研究还未结束 | “已经完成的部分得到了什么结果，哪部分还没有验证？” | R，当前进展与不足 |

根据研究类型继续选择，不一口气问完：

- **数据与模型研究**：数据来源与适用范围、预处理、方法实现、训练和验证的关系、比较对象与指标条件。只有材料确实涉及这些环节时才问，不预设用户负责完整流程。
- **实验与测量研究**：观测对象、关键条件、仪器或测量方式、对照与重复、结果如何形成。根据研究本身调整，不强制每项研究都有同一种实验设计。
- **调查、文本或理论研究**：研究问题、材料选择、调查或分析过程、判断依据、结论边界。不能因为没有准确率或硬件而认为无法形成结果。

当用户讲出多个阶段时，先理清各阶段在解决什么问题，再决定分成几段。不要仅根据方法名称推断“克服了某种局限”；没有实际比较时，使用“尝试”“用于评估”等符合进展的表述。

## 竞赛项目

| 已知内容或缺口 | 可选的下一问 | 要得到的信息 |
| --- | --- | --- |
| 只知道比赛名称 | “这次赛题要求你们完成什么作品或任务？” | S/T，赛题与交付要求 |
| 比赛内容很宽泛 | “你们最终选择了哪个具体问题？” | S，方案范围 |
| 团队方案清楚但分工不清 | “哪一部分是你负责交付的？” | T，个人任务 |
| 只说做了一个方案 | “你的部分从开始到提交，实际经过哪些步骤？” | A，工作过程 |
| 方案发生变化 | “是哪条测试结果或评审意见让你们作出调整？” | A，迭代依据 |
| 只说用了某种技术 | “这项技术解决了作品中的哪个具体任务？” | A，技术与需求的关系 |
| 团队获奖 | “除了奖项，你自己完成了哪些具体产物？” | A/R，个人贡献与团队结果分别说明 |
| 只有展示或答辩结果 | “有哪些测试记录、展示效果或评审反馈可以准确说明？” | R，结果依据，不推测未公开的评分原因 |
| 奖项名称或层级模糊 | “奖项的准确名称和所属赛段是什么？不确定可以先留待核实。” | R，奖项口径 |
| 作品未获奖或尚未参赛 | “目前已经完成了什么，哪里还没有达到要求？” | R，阶段结果与不足 |

评分规则可以帮助理解任务，但不能倒推出用户做过的工作。评委认可、团队排名、技术指标和实际部署效果分别记录，不相互替代。

## 类别不明确或只有一段普通任务

先使用通用问题：“你接到什么任务、亲手做了什么、交付了什么、怎样知道完成了。”已有这些事实就可以形成经历，不必先给项目贴上科研或竞赛标签。

对用户不清楚的专业细节，可以先作简短解释帮助其核对，但不将常见方案或外部案例合并进个人事实。用户说没有做过时停止该方向的追问，回到实际参与范围。
